# Intent v1 开发计划

> 2026-10-25 开始。依据：`intent-design-spec.md`（v1.1 定稿）、`agent-runtime-design.md`。
> 旧数据和旧界面全部不要，从新建开始；旧代码在 git 历史里可以找回。

## 架构决定

| 决定 | 内容 | 原因 |
|---|---|---|
| agent 大脑放在本仓库 | `server/`：提示词、工具、调用循环、平台适配器、规则（永远不做、花费上限）。部署为 Vercel 函数 `api/`；本地开发时由 Vite 插件挂同一套处理函数 | 提示词和工具要跟界面一起反复调；不再有旧网关架构，浏览器只用 anon key 的前提已经不存在 |
| 模型平台可替换 | 适配器只依赖「OpenAI 兼容的 chat completions + 工具调用」这一最大公约数；开发期走 OpenRouter `anthropic/claude-haiku-5.5`。以后加 Anthropic 直连或 Managed Agents，只是多一个适配器 | DZ：不能绑死一家平台；本机目前没有可用的 Anthropic key |
| 搜索也可替换 | `SearchProvider` 接口，默认用 OpenRouter 的 web 插件（约 $0.012/次） | 同上 |
| 状态归我们 | 每件事的完整时间线（话、追问、计划、点头卡、结果）存在我们自己的库里；每一轮都从库里重建上下文，平台会话可以随时丢 | 换平台不迁数据 |
| 数据持久化 | 当前由本仓库的 server/store 管理本地 JSON；后续生产数据库迁移在 Intent 内独立规划 | 不依赖其他产品仓库 |
| 实时更新 | v1 先轮询（有事在办时每秒取一次），以后换 Supabase Realtime | 本地和线上同一套，最简单 |
| 先用后注册 | 第一次打开发一个设备身份（M1）→ Supabase 匿名登录 + 邮箱验证码升级为正式账号（M2） | 设计稿 6.1 |

## 里程碑

**M1：核心闭环真能用（本地）**
- 新界面：今天 / 说一件新的事 / 一件事 / 我的；中英文；适老默认（20px 正文、60px 主按钮、字号 3 档真生效）。
- 帮手：追问（选项按钮）→ 计划（好，开始 / 改一改）→ 在办（查网页、比价）→ 等您点头（买东西：5 要素卡片，受上限约束，永远不做清单在服务端强制）→ 结果 → 办完。
- 「这是不是骗子？」入口。朗读、语音输入（点一下开始、点一下结束）。
- 端到端测试用脚本化的假模型，不花钱、结果固定；另有一个真模型冒烟测试。
- 删除旧界面、旧网关代码和旧测试。

**M2：上线**
- 在 Intent 项目内规划生产数据表、访问隔离与账户恢复。
- 存储切到 Supabase（服务端用 service-role，按用户 JWT 校验归属）。
- 选择支持完整 Node 服务的托管环境，配置服务端模型凭据与持久化；正式域名尚未确定。

**M3：盯着和提醒**
- 定时跟进（`schedule_followup`）、提醒、价格盯梢；浏览器推送 + 邮件（Resend）。

**M4：家人帮手前两档 + 家长给孩子开账号**

**M5：付款第二步**（agent 支付协议 / 虚拟卡），订阅收费。

可用性测试（5 位 60 岁以上的人）在 M1 完成后就开始，和 M2 之后的开发并行。
